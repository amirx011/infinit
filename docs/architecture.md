# معماری Infinit Lab

## ۱. هدف طراحی

سه constraint اصلی پروژه:

1. **دقت کامل**: هیچ حل‌کننده‌ای نباید جواب تقریبی را به‌جای جواب دقیق ارائه کند.
2. **قابل اجرا روی اندروید و لینوکس** بدون وابستگی به مفسر سنگین پایتون.
3. **شفافیت**: کاربر باید ببیند جواب چگونه ساخته شده و کجا فرض یا انتگرال غیرمقدماتی وجود دارد.

به همین دلیل، محاسبات در یک هستهٔ بومی C++17 انجام می‌شود و UI فقط نمایش‌دهندهٔ نتیجه است.

## ۲. لایه‌ها

### ۲.۱. هستهٔ جبر (`core/src`)

| فایل | مسئولیت |
|---|---|
| `expr.hpp/.cpp` | AST، `Rational`، ساخت/ساده‌سازی متعارف، ترتیب، چاپ، جایگذاری، `Deriv` |
| `parse.cpp` | تحلیلگر بازگشتی نزولی، ضرب ضمنی، پریم، `dy/dx`، نویسه‌های یونیکد |
| `algebra.cpp` | بسط، `together`، حذف عوامل مشترک، حل خطی، ریشهٔ چندجمله‌ای، اتحادهای مثلثاتی |
| `calculus.cpp` | مشتق، انتگرال (جدول، جایگذاری u، جزءبه‌جزء، توان مثلثاتی، کسرهای جزئی) |
| `poly.cpp/.hpp` | حساب چندجمله‌ای، تجزیه، کسرهای جزئی، انتگرال توابع گویا |
| `ode.cpp` | حل‌کننده‌های ODE، رونسکی، پوش، تولید گام‌های فارسی |
| `numeric.c/.h` | ارزیاب RPN در C99 برای گواهی عددی |
| `numeric.cpp/.hpp` | کامپایل AST به RPN و توابع `numericallyZero` / `numericallyEqual` |
| `api.cpp` | JSON parser/writer سبک، C ABI، تبدیل `Result` به JSON |

#### نمایش اعداد

`Rational` یک جفت `int64` است. هر عملیات با `__int128` انجام و سپس بررسی سرریز می‌شود. در صورت سرریز `OverflowError` پرتاب و در API به پیام فارسی تبدیل می‌شود. اعداد اعشاری ورودی به نزدیک‌ترین کسر دقیق با مخرج توان ۱۰ تبدیل می‌شوند؛ هیچ `double` در مسیر تولید جواب وجود ندارد.

#### AST

گره‌ها: `Num`, `Sym`, `Add`, `Mul`, `Pow`, `Func`.

- `Add` و `Mul` flat و مرتب‌شده‌اند.
- `Deriv(y, x, n)` یک **jet variable** مستقل در جبر ODE است؛ `dependsOn(Deriv(y,...), "y")` عمداً `false` است تا حل‌کننده بتواند ضرایب را از ترم مشتق جدا کند.
- `Integral(f, x)` یک گرهٔ صادق برای انتگرال غیرمقدماتی است.

#### ساده‌سازی

`simplify` بازگشتی است و شامل:

- جمع جمله‌های مشابه و ضرب توان‌ها
- `sin²u + cos²u = 1`
- `(e^u)^v = e^{uv}`
- `together` و `cancelCommon` برای کسرها
- فاکتورگیری عوامل مشترک

هدف `simplify` «کوچک‌ترین نمایش ساختاری» است، نه یک CAS کامل. به همین دلیل هر جواب نهایی با مشتق‌گیری و جایگذاری راستی‌آزمایی می‌شود.

### ۲.۲. حل‌کننده‌های ODE (`ode.cpp`)

ترتیب تشخیص برای مرتبهٔ اول:

1. شکل دیفرانسیلی `M dx + N dy = 0` → کامل / عامل انتگرال‌ساز
2. حل برای `y'`
3. خطی مرتبهٔ اول
4. جداشدنی
5. همگن
6. برنولی
7. ریکاتی (جواب خصوصی یا تبدیل مرتبهٔ دوم)
8. جایگذاری خطی `u = ax + y`
9. کامل/عامل انتگرال‌ساز از ضرایب
10. انتگرال‌گیری مستقیم

کلرو و لاگرانژ **قبل** از حل برای `y'` بررسی می‌شوند، چون در `y'` غیرخطی‌اند. برای اینکه معادلهٔ خطی/کامل به‌اشتباه لاگرانژ تشخیص داده نشود، درجهٔ چندجمله‌ای نسبت به `p = y'` بررسی می‌شود.

مرتبهٔ دوم:

- `y'' = f(x)` → انتگرال‌گیری دوباره
- خطی همگن با ضرایب ثابت → چندجمله‌ای مشخصه، تجزیه، ریشه‌های حقیقی/مختلط/تکراری

### ۲.۳. گام‌ها و مدل نتیجه

`Result` شامل:

- `typeId` / `typeFa`
- `solution` (ضمنی یا صریح)، `explicitY`
- `paramX`, `paramY` برای لاگرانژ
- `singular` برای جواب‌های منفرد
- `steps` به‌صورت `Step{title, math, note}`
- `checks` به‌صورت `Check{name, ok, detail}`
- `warnings` و `assumptions`
- `closedForm`

گام‌ها در C++ ساخته می‌شوند تا منطق فارسی و ریاضی یک‌جا بماند؛ UI فقط آن‌ها را رسم می‌کند.

### ۲.۴. اعتبارسنجی

دو مکانیزم:

1. **نمادین**: مشتق جواب صریح گرفته و در معادله گذاشته می‌شود؛ برای جواب ضمنی از رابطهٔ `u_x N − u_y M` استفاده می‌شود.
2. **عددی**: `numeric.cpp` عبارت را به RPN کامپایل می‌کند و در چند نقطهٔ نمونه (نه صفر و نه یک) مقدار می‌گیرد. این لایه فقط **گواهی** است و در تولید جواب دخالتی ندارد.

اگر انتگرال غیرمقدماتی وجود داشته باشد، بررسی نمادین ممکن نیست و `closed_form=false` گزارش می‌شود.

### ۲.۵. C ABI و FFI

```c
char*       ode_solve(const char* request_json);
void        ode_free(char* text);
const char* ode_core_version(void);
```

- ورودی/خروجی UTF-8 JSON است.
- خروجی با `malloc` ساخته می‌شود و با `ode_free` آزاد می‌شود.
- فراخوانی بدون وضعیت (stateless) است؛ هر درخواست مستقل است.
- Flutter با `dart:ffi` و `package:ffi` این دو تابع را صدا می‌زند.

مسیر جست‌وجوی کتابخانه در `app/lib/src/native_engine.dart`:

1. `INFINIT_LIB`
2. `<exe>/lib/libodecore.so`
3. `<exe>/libodecore.so`
4. `libodecore.so` (برای اندروید)
5. مسیرهای توسعهٔ محلی

### ۲.۶. UI

- Flutter، Material 3، فونت Vazirmatn
- **چندزبانه**: ۱۲ زبان رابط (انگلیسی پیش‌فرض) با چیدمان RTL/LTR خودکار؛ متن حل‌های هسته فقط انگلیسی یا فارسی است
- **صفحهٔ تنظیمات**: ظاهر یکپارچه (تم، پالت، کنتراست، کاهش حرکت)، زبان، اندازهٔ متن، حل مرحله‌به‌مرحله، بررسی اعتبار، نمودارها، رقم‌های اعشار، صفحهٔ شروع و بازگردانی پیش‌فرض‌ها (`settings_page.dart`)، با ذخیرهٔ انتخاب کاربر (`settings_store.dart`: فایل JSON در لینوکس، `SharedPreferences` در اندروید)
- **۲۷ صفحهٔ ابزار**: مشتق، انتگرال، کاربردهای انتگرال، تیلور، مشتق جزئی، سری، معادلات دیفرانسیل، رونسکی، پوش/مسیرهای قائم و مایل، و کاربردهای مشتق
- داشبورد خانه برای مشتق/انتگرال/ODE؛ رونسکی، پوش و مسیرها در منوی کناری
- نمایش ریاضی با جهت LTR مستقل از جهت رابط؛ فرمول‌ها با چیدمان واقعی LaTeX (کسر، رادیکال، انتگرال) و نه متن خطی
- کپی `LaTeX` برای هر عبارت
- نمایش گام‌ها، گواهی‌ها، هشدارها و فرض‌ها که هر کدام در تنظیمات قابل خاموش‌کردن‌اند؛ هر بخشی که نمودار معنادار دارد آن را رسم می‌کند (میدان جهت، منحنی جواب، نمودار تابع و مشتق، مجموع جزئی، نقشهٔ تراز) و نمایش همهٔ نمودارها نیز از تنظیمات قطع می‌شود
- گام‌ها و خطاها در هسته به زبان درخواست (`lang`) تولید می‌شوند

### ۲.۷. اوراکل پایتون

`python/infinit_engine`:

- `solve_ode`: `classify_ode` + `dsolve` + راستی‌آزمایی جایگذاری
- `wronskian`: دترمینان ماتریس مشتق‌ها
- `envelope`: حذف پارامتر و تشخیص حالت تبهگن
- `oblique`: شیب خانوادهٔ مسیرهای مایل از رابطهٔ زاویهٔ ثابت
- `verify_candidate`: بررسی جواب بومی (صریح یا ضمنی) با SymPy

این بخش **در APK قرار نمی‌گیرد**. فقط برای تست، تولید آزمون و راستی‌آزمایی مستقل است.

> اوراکل فعلی حالت‌های ODE، رونسکی، پوش و مسیرهای قائم/مایل را پوشش می‌دهد؛ مشتق و انتگرال نیز مستقیماً در هستهٔ بومی و تست‌های Flutter بررسی می‌شوند.

## ۳. جریان یک درخواست

```
UI (Dart)
  └─ NativeEngine.solveOde(...)
       └─ jsonEncode → ode_solve()
            └─ parse JSON
            └─ solveODE(...)
                 ├─ parseODEExpr
                 ├─ تشخیص نوع
                 ├─ حل + ساخت Step/Check
                 └─ Result
            └─ resultJson (plain/pretty/latex)
       └─ SolveResult.fromJson
  └─ ResultView (RTL)
```

## ۴. تصمیم‌های مهندسی

- **بدون Chaquopy/SymPy روی اندروید**: حجم، مجوز، سازگاری ABI و زمان راه‌اندازی. هستهٔ بومی سریع‌تر و قابل پیش‌بینی‌تر است.
- **C برای ارزیاب عددی**: سطح تماس کوچک، قابل کامپایل با NDK، بدون وابستگی.
- **JSON به‌جای struct FFI**: نسخه‌پذیری آسان، دیباگ ساده، توسعهٔ مستقل UI و هسته.
- **گام‌ها در هسته**: یک منبع حقیقت برای ریاضی و متن فارسی.
- **Integral node**: به‌جای جعل یک جواب بسته یا تقریب، انتگرال باقی می‌ماند و پرچم می‌خورد.
